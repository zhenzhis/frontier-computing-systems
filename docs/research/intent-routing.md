# 意图分流：两轮研究与暂缓决定

**决定日期：2026-10-14；状态：暂缓采用。** 用户选择先保持手动模型选择。保留技术路径和评价方法，未在工作流安装分类器，也未变更 Magpie 路由、默认模型或推理强度。

## 第一轮：入口自动选择、意图与决策模型

斜线入口是任务方法的快捷方式；当前 agent 也能根据目标、阶段和证据使用合适的方法，不必增加专用分类请求。方法选择不能授权副作用，也不等于把请求转到另一个模型。

Magpie 的模型组、规则、会话保持和可用性回退可以作为分流底座。评价必须区分规则选择、模型意图判断、成员回退和真正的语义验收。廉价决策模型适合高吞吐、低风险、短输入、结构化且可拒判的分类，复杂需求、未知原因调试与跨文件改动应明确交给强角色。Jev、Laya 等候选需要核对实际接口、输出协议、误判、延迟和成本，品牌名称不能证明能力。

模型组向 agent 宣告最大窗口时，较小成员仍可能无法继续当前对话；长输入首先需要兼容性过滤。切换模型、Provider 或努力等级会影响缓存与上下文解释，保持一个工具回合的连续性，再在任务边界重新考虑。

## 第二轮：能力排名与本地组合审计

排行榜只能筛候选。编码、视觉、指令遵循、结构化输出、检索、速度与成本需要分别考察；同一基础模型通过两个渠道不等于两个独立审查者。订阅、转发渠道和 `/models` 清单不能证明模型的真实底座、满血上下文表现或可用额度。

先固定强模型基线，再比较手动职责分工与候选分流：首遍验收、成功交付耗时、返工、总成本、误把难任务分到轻模型的比例、回退后的信息保真。使用开发集调试、选择集选方案、最终保留集报告。不要通过每轮改变努力档位制造分类延迟和行为抖动。

## 将来如何重新评估

先离线记录建议而不改变真实路由；验证结构化协议、置信度/拒判、边界用例和高风险漏判。再在明确授权的低风险任务中灰度，对照强基线，设定有限预算、回退和停止条件。保持人工强角色选择入口；发布、部署、删除、消息和计费授权仍单独校验。没有实测收益则继续手动方案。
