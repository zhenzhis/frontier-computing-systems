# FCS 命名、定位与研究规范决策

日期：2026-10-16。决定：采用命名与研究规范；不据此变更活动 Pi 配置或采纳意图分流。

## 正式命名

| 用途 | 规范 |
|---|---|
| 项目及 GitHub 展示名称 | Frontier Computing Systems |
| 正式研究计划 | Frontier Computing Systems Research |
| 日常简称 | FCS |
| 仓库及源码目录 | `frontier-computing-systems` |
| 内部短标识 | `fcs` |
| 研究方向副标题 | Agent Systems, Harnesses & Evaluation |
| 当前工程实现 | FCS Pi Workflow |

理由：原名称描述具体工作流，新的范围包含 Agent、Harness、工具、记忆和评测，适合作为长期研究与工程项目。Research 用于计划名称，避免在项目名中重复堆叠。Computing Systems 范围较广，因此公开入口补充具体研究方向；当前优先范围不扩展为泛化的计算科学。

FCS 不是全球唯一缩写。外部引用优先用完整项目名或仓库 owner/name；没有据此进行商标或全球名称独占性认定。Frontier 表达探索方向，不能作为性能或科研水平的证明。

## 与先进研究系统对照

以下是一手公开资料中的方法对照，不是完整前沿排名或本项目能力对标。阅读日期为本记录日期；本次没有复现这些外部系统。

| 对照对象 | 公开材料支持的方法 | 本项目采用的原则与限制 |
|---|---|---|
| [Google AI co-scientist](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/) | 生成、反思、排序和改进科学假设，结合专家和实验验证；文章同时说明自动评分与评估限制 | 借鉴问题、假设、实验、复核闭环；不把模型互评的高分等同于真实改进，也不因其多 Agent 结构而默认增加代理 |
| [SakanaAI AI Scientist-v2](https://github.com/SakanaAI/AI-Scientist-v2) | 假设、实验、分析与写作，使用 Agentic Tree Search；作者明确更广泛探索并不总优于有良好模板的 v1 | 记录实验分支和失败，先评估探索成本与收益；不照搬全自动论文流水线或声称通用自主科研能力 |
| [Anthropic Agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 模型与 Harness 共同构成评估对象；区分轨迹与环境结果、能力与回归评测，并组合适合的评分器 | 固定完整条件，以产物独立验收，重复运行并保留回归证据；不把模型名称、CLI 成功输出或自报字段当作性能结论 |

当前项目已经具备版本、有限任务记录、恢复、候选经验与验证工具等工程基础；这与已经完成代表性研究评测是两件事。已有工程测试证明其覆盖的行为，不证明实际长任务质量、模型渠道性能或自主研究能力。下一步先建立真实任务基线，再按问题研究上下文恢复、记忆和受控自动化；没有本轮新性能数值。

## 落地与兼容

研究工作采用 [研究纲领](../../RESEARCH.md) 和 [记录模板](../../templates/研究记录.md)，复杂度与主张相称，不为每次小修改增加研究流程。

仓库更名沿用原历史；旧 tag、版权、第三方出处与私人备份不重写。当前运行协议、状态目录、命令和资源标识保留兼容，避免名称变更隐式破坏已有账本。更名本身不作为运行时版本发布；具体规则见 [维护规范](../maintenance.md)。

保留并继续遵守此前决定：先备份，功能优化先在获授权的本地部署验收，再整理脱敏公开候选、备份源码、检查精确提交 CI 并发布不可变版本。项目身份与文档变更适用无需修改活动配置的例外。研究材料不授权账号变更、自动路由、后台任务、外部发信或新费用。
