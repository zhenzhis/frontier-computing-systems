# 架构与边界

Frontier Computing Systems（FCS）是研究项目；当前工程实现称为 **FCS Pi Workflow**。研究范围与验证方法见 [研究纲领](../RESEARCH.md)。现有 Pi 包、控制器和状态协议不是一个已经完成的通用自主研究系统。

本项目把可移植工作流源码、用户运行状态、真实部署配置分开。公开源码由 Git 和固定依赖管理；任务账本在用户目录；Provider、认证、MCP 和私人会话由 Pi 自己的配置目录管理。

```mermaid
flowchart LR
  A[用户目标与授权] --> B[按需方法与任务记录]
  B --> C[检查 scope / revision / budget]
  C --> D[显式 arm]
  D --> E[一次有限工作器执行]
  E --> F[独立工程验收]
  F --> G[人工或已授权的控制器评审]
  G --> H[完成 / 修复 / 暂停]
  H --> I[候选经验与单变量实验]
```

`managed/extensions/workflow-baseline` 只提供版本、完整性与上下文提醒。`workflow-runtime` 提供本地记录命令；不从自然语言推断执行授权。`runtime/control.mjs` 管理追加账本、哈希链、revision、预算和单写者锁。`worker.mjs` 只有显式执行参数才发起模型请求；实现阶段仅允许已声明文件的写入。`evaluate.mjs` 运行使用者提供的可信检查，不执行来自反馈的任意命令。

这些约束不是操作系统沙箱。普通 Pi 会话和别的程序可以绕过工作器的文件锁；记录中的独立验收字段也不是独立审查已经发生的证明。真正的验收必须对应实际产物和执行证据。

启动时只加载两个小扩展与资源索引；模板和 Skill 按任务取用。默认不加分类器、轮询、常驻服务、全套框架或后台自动工作器。主题提供低饱和配色，不替换 TUI footer/editor；现有视觉插件可单独评估兼容性。

模型能力、请求可用性、任务方法和操作授权是四个不同问题。最大上下文是端点声明容量；192K 是阶段整理的试用提醒，不是经过所有模型验证的最佳注意力长度。性能判断应比较成功交付时间、返工、成本和恢复后的信息保真。

研究背景见 [研究索引](research/README.md)，操作协议见 [运行手册](../runtime/README.md)。
